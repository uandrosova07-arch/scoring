# Как считается оценка риска

Для всей команды. Сервис `scoring` смотрит на финансы компании и возвращает уровень риска с объяснением.
Кредитное решение принимает backend (C#) по политике банка. Если `scoring` недоступен, backend считает
по встроенным правилам и помечает результат как fallback.

Расчёт построен на правилах, а не на обученной модели: одинаковые данные всегда дают одинаковый ответ.

## Три правила

1. **Достаточность сведений.** Нужны пять показателей: выручка, расходы, ежемесячные платежи по кредитам,
   запрошенная сумма и срок. Если хоть одного нет, уровень риска `undetermined`, а в `missing_data` перечислено,
   чего не хватает. Backend может по этому списку запросить данные у клиента.
2. **Расходы к выручке** (за 12 месяцев).
3. **Кредитная нагрузка.** Текущие ежемесячные платежи плюс новый платёж (сумма / срок), делённые на месячную
   чистую прибыль. Если чистая прибыль за год не положительна, нагрузку считать не из чего: это сразу высокий риск.

## Пороги (предварительные, нужно согласовать с продактом и backend)

| Показатель | Низкий | Средний | Высокий |
|---|---|---|---|
| Расходы / выручка | меньше 70% | 70–90% | больше 90% |
| Кредитная нагрузка | меньше 30% | 30–70% | больше 70% |

## Итоговый уровень

Берётся худший из результатов правил: любой «высокий» даёт `high`, иначе любой «средний» даёт `medium`,
иначе `low`. Если данных не хватает, итог `undetermined`.

## Коды причин

`INSUFFICIENT_DATA`, `EXPENSE_RATIO_OK|MODERATE|HIGH`, `DEBT_LOAD_LOW|MEDIUM|HIGH`, `NO_PROFIT`.
В ответе у каждой причины есть код, текст для человека и числовое значение, по которому она получена.

## Упрощения

- Новый платёж считается как сумма / срок, без процентов.
- Чистая прибыль берётся из запроса, а если её нет (`null`), считается как выручка минус расходы.
- Возраст бизнеса пока в правилах не участвует.
