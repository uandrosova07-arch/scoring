# Интеграция logreg-synthetic-0.1

25 октября 2026. Коэффициенты модели сохранены; обновлены runtime, общий артефакт и проверки совместимости.

## Что изменилось

- Одинаковый JSON используется Python и C#. /health Python возвращает artifact_sha256 загруженных байтов; readiness backend проверяет версию и SHA256, чтобы внешний и резервный расчёт не разошлись незаметно.
- При отказе Python backend использует локальный inference той же модели и сохраняет source=RulesFallback, modelVersion=logreg-synthetic-0.1. Старый rules-0.3 остаётся отдельным явным выбором.
- Входы общего эталона используют GUID в request_id. Добавлен 33-й случай demo-reduced.
- Объяснения не утверждают наличие просрочек/производств при отсутствии ответа БКИ/ФССП. Указаны статистическое заполнение и пропуск. Показатели налогов/истории описываются относительно обучающей выборки.
- Отпечаток данных имеет формат observed-columns-json-v1: наблюдаемые столбцы и целевая разметка, фиксированный порядок, null, целые числа, остальные значения до 12 значащих цифр. Диагностические скрытые float-столбцы не входят в fingerprint обучения. Исходный хеш сохранён в legacy_dataset_sha256; коэффициенты не менялись.

## Профиль уменьшенной суммы

Новый backend-логин client_reduced / Demo123!, ООО «Развитие», ИНН 7702234567. Выручка 9.6 млн, расходы 7.68 млн, чистая прибыль 1.536 млн, текущие платежи 100 тыс./мес.; бизнес с 01.06.2023, прошлые просрочки до 25 дней, налоговый долг 12 тыс., без стоп-факторов.

Заявка working-capital, 3 млн на 24 месяца: модель около 61/C, решение 2.4 млн под 22.5%, платёж 125100.96. Профиль добавляется идемпотентным seed, старые компании не переписываются. Это демонстрационный профиль, не индивидуально зафиксированный грейд.

## Проверка

- python -m pytest -q (с requirements-train.txt — также обучение и fingerprint).
- python scripts/e2e_backend.py --mode External --model logreg-synthetic-0.1 --api http://localhost:18081 --scoring http://localhost:18001
- После остановки только тестового scoring повторить с --mode RulesFallback.
- Для C# — общий data/conformance/logreg-synthetic-0.1.json, PD/логит с допуском 1e-9, score/grade/factors совпадают.

В обоих режимах положительные сценарии должны дойти до Disbursed, отказ не должен создавать договор. Скрипт для logreg проверяет также совпадение totalPayment/totalInterest оффера и договора. Старый --model rules-0.3 продолжает использовать прежние пять сценариев.

## Включение

Backend и ML должны использовать одну модель и один файл. В backend: Scoring:ModelVersion=logreg-synthetic-0.1, Scoring:Mode=External. В Python: SCORING_MODEL=logreg-synthetic-0.1. При локальном Compose задавать SCORING_MODEL и собирать оба обновлённых checkout; старый закреплённый GHCR-образ rules не содержит нового артефакта. Не переобучать модель при старте API.

Качество и все метрики относятся к синтетическим данным. Новая runtime-версия не делает их оценкой реального портфеля.
